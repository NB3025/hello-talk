# 앞으로 붙일 서비스 (ROADMAP)

카카오 서비스를 두 차례 조사해 추린 목록이다. **화면에 `오픈 예정` 으로 표시되는 항목의
단일 출처는 `src/domain/roadmap.ts` 이고, 이 문서는 그 목록의 근거를 담는다.** 목록을 문서에만
적어두면 화면과 반드시 어긋나므로 이름·자리·상태는 코드가 들고 있다.

조사일 2026-09-09. 카카오 공식 출처(`kakaocorp.com`, `cs.kakao.com`, `developers.kakao.com`,
앱스토어 설명)를 1차로 썼고, 확인하지 못한 것은 아래에 그대로 `확인 불가` 로 남겼다.

## 왜 이 목록인가 — 결합 패턴이 3개다

개별 기능보다 **카카오톡이 외부 서비스를 끌어들이는 방식**이 더 쓸모 있었다. 세 가지로 수렴한다.

| 패턴 | 뜻 | 실제 사례 |
|---|---|---|
| **A. 대화에 카드를 흘린다** | 카드가 상태를 텍스트로 굳히지 않고 원본에서 매번 읽는다 | 선물 말풍선, 톡게시판 글의 자동 말풍선, 톡캘린더 메시지, 채널 쿠폰, 알림톡 |
| **B. 친구 그래프만 빌려간다** | 화면은 밖에 있고 관계망만 가져온다 | 계좌번호 없이 카톡 친구에게 송금, 카카오뱅크 이체, 카카오맵 친구위치가 톡 프로필 사용, 개발자 `카카오톡 소셜` API |
| **C. 별도 공유 컨테이너를 만들고 친구를 초대한다** | 대화가 아닌 제3의 객체 | 카카오뱅크 모임통장, 카카오맵 친구위치 그룹, 팀채팅 |

**패턴 A 는 이미 구현돼 있다** — `GiftBubble` 이 그것이고, 같은 모양이 톡게시판과 톡캘린더에서도
독립적으로 확인됐다. 앞으로 붙일 것도 이 형태를 재사용하면 새 인프라가 필요하지 않다.

**패턴 C 가 조사에서 가장 값진 발견이다.** 카카오는 그룹 단위 일(공동 지출, 위치 공유, 팀 협업)을
대화에 흘리지 않고 제3의 객체를 만든 뒤 관계망을 그 안으로 끌어온다. 정산을 넣을 때 "방에
메시지 하나"로 만들면 카카오의 답과 다르다.

카카오맵 친구위치는 세 패턴이 겹친 사례다 — 채팅방 `+` 에서 시작(A), 톡 프로필·닉네임을 그대로
사용(B), 그룹 컨테이너를 만들고 그 안에 다시 채팅을 넣는다(C). 카카오맵 공식 블로그의 표현이
정확하다: **"출발했어? 어디야?"라는 대화 자체를 지도로 대체하는 설계**다.

## 다음 슬라이스 후보 — 지금 구조에 그대로 얹힌다

### 1. 캘린더 (일정 + 할 일)

**'약속'이라는 개념은 카카오 공식 문서에 없다.** 실제 축은 **일정(event)** 과 **할 일(task)** 이고,
일정은 `USER`(일반) / `TEAM`(공유, 개념만 있고 API 미지원) / `PUBLIC`(채널이 발행) /
`SUBSCRIBE`(구독) 4종이다. 여기에 공개 일정을 내 캘린더에 담은 **게스트 일정**이 있다.

'약속 + 참석 수락/미정'은 **네이버 캘린더의 개념**이다. 검색 색인이 네이버 도움말로 심하게
편향돼 있어 그대로 옮기면 치명적 오류가 된다.

톡캘린더는 **카카오가 REST API 로 스키마를 공개한 유일한 기능 중 하나**라서 추측 없이 옮길 수
있다:

- 캘린더 3종 — 기본(`primary` 고정 ID, 추가·삭제 불가) / 서브(사용자당 **최대 99개**) / 구독(채널 발행)
- 할 일은 별개 타입 — 기한, `RRULE` 반복, 즐겨찾기, `SCHEDULED`/`COMPLETED`/`DELAYED`, **도전 기록**(반복 할 일의 완료 이력)
- 미리 알림 — 5분 간격, **최대 2개**, 시작 30일 전까지
- 시간 정보에 **`lunar` 불리언**(음력)
- 기간 프리셋 `TODAY` / `THIS_WEEK` / `THIS_MONTH`, **주는 일요일 시작**
- 캘린더·일정 단위 색상

**참석 응답(RSVP)에는 근거가 없다.** 초대 개념은 `is_host` 정의("공개/구독 일정 **또는 초대 받은
일정**인 경우 `false`")로 확인되지만, 참석 상태에 해당하는 필드가 API 전체에 하나도 없다. 공유
캘린더도 제품엔 있고 API 는 "지원 예정"이므로 API 부재가 UI 부재를 증명하지는 않는다 —
**판정 보류**다. 만든다면 우리가 발명한 것이라고 표시해야 한다.

**일정 초대는 친구 관계를 요구하지 않는다.** 톡캘린더에 "카카오톡 친구가 아닌 이용자가 나를
일정에 초대"하는 경우가 있어 '친구의 일정 초대만 알림 받기' 설정이 따로 있다. 참석자를 친구
목록으로만 제한하면 실제와 어긋난다.

**주의 — 구현 전에 확인할 것**: `prototypes/gift-calendar-placement.prototype.html` 에서 요일이
1일 밀리는 버그를 한 번 잡았다. 그때 고친 offset 이 일요일 시작 기준이었는지 다시 봐야 한다.

출처: [톡캘린더 이해하기](https://developers.kakao.com/docs/ko/talkcalendar/common),
[톡캘린더 REST API](https://developers.kakao.com/docs/ko/talkcalendar/rest-api)

### 2. 펑 (Pung)

24시간 뒤 사라지는 프로필 게시물. 공개 범위는 전체 / 내 친구 / 친한 친구 / 나만 보기 4단계이고,
전체 공개는 친구가 아닌 사람에게도 공유될 수 있다.

**우리 원칙과 같은 종류의 문제다.** 사라짐을 저장하면 "지워주는 사람"이 필요해지고 그 사람이
없는 순간 틀어진다 — 안읽음과 선물 만료를 저장하지 않고 계산하는 것과 같다. 기존 셀렉터 패턴을
재사용하면 거의 공짜로 구현된다.

### 3. 위시리스트

`선물하기 > 위시` 탭. 상품 상세의 하트로 담고 **친구공개 / 나만보기** 중 고른다. 최대 **1,000개**,
초과하면 가장 먼저 담은 것이 자동 삭제된다. 친구 위시가 비어 있으면 **"친구에게 물어보기"** 로
담아 달라는 메시지를 보내고, 받은 쪽이 그 메시지를 통해 응답한다 — 선물↔채팅 왕복이다.

모델이 단순하다: `{ userId, productId, visibility }`. 이 프로젝트에서 위시 탭을 뺀 이유가
"모델이 없어서"였는데, 이 정도면 있다.

출처: [위시리스트 도움말](https://ccs.kakao.com/help?service=66&category=13374&device=13378)

### 4. 팀채팅 · 그룹 채팅방 만들기

`Chat.memberIds` 는 이미 3명 이상을 담고 화면도 인원수를 표시하는데 **방을 만드는 경로가 없다.**
이것이 선물게임·코드선물·메시지 가시성의 선결 조건이라 한 묶음이다.

**팀채팅**은 공지·투표가 중심인 방이다. 카카오는 채팅방마다 **톡게시판**을 제공하는데("모임에
필요한 공지와 투표는 물론 파일 공유도"), 글에 텍스트·이모티콘·사진·동영상·파일·**투표**를
첨부하고 공지로 등록할 수 있으며, **글이 올라오면 채팅방에 말풍선이 자동 발송**된다. 흐르는
대화로는 합의가 되지 않기 때문에 따로 있는 구조다.

**그룹방 읽음 표시는 방향이 반대다.** 메시지 옆 숫자는 읽은 사람 수가 아니라 **"이 메시지를
읽지 않은 인원수"** 이고 그룹방은 **최대 99** 까지만 표시한다. 1:1방의 `1` 도 같은 의미다.
현재의 방 목록 배지("내가 안 읽은 남의 메시지 수")와는 다른 개념이므로 메시지별 표시를 붙일
때 뒤집어야 한다.

**조용히 나가기**는 실질적으로 **일반 그룹채팅방 안에서 나갈 때만** 동작한다 — 목록에서
스와이프/롱탭 나가기, 목록 편집 나가기, '초대거부 및 나가기', 1:1·오픈채팅·비밀채팅 나가기,
팀채팅 방장 나가기에는 적용되지 않는다.

### 5. 이모티콘 — 구독권이라는 세 번째 상품 종류

**이모티콘 플러스 구독권은 선물할 수 있다.** 카카오 공식 이모티콘 페이지에 `이모티콘 플러스
선물하기` 버튼이 직접 배치돼 있다. 즉 **월 구독 상품이 카톡 관계망 위에서 상품으로 오간다.**
현재 카탈로그는 실물 배송과 교환권만 다루므로 종류가 하나 더 필요하다.

**이름 함정 — 카카오페이지·카카오웹툰의 "선물함"은 친구 간 선물이 아니다.** 공식 설명이 "오늘의
선물함에서 매일 새로운 작품의 이용권을 무료로 받을 수 있어요"로, **플랫폼→이용자 무상 지급
창구**다. 우리 `GiftBox`(선물함)와 이름만 같고 의미가 반대다.

멜론 이용권의 카톡 선물하기 등재 여부는 **확인 불가**(2015년 팬 블로그 하나뿐).

출처: [카카오 이모티콘](https://www.kakaocorp.com/page/service/service/KakaoEmoticon)

## 구조를 늘려야 하는 것

### 6. 선물게임 · 코드선물 · 메시지 가시성

**1:1방과 그룹방에서 선물하기가 완전히 갈린다.**

1:1방은 받는 사람이 자동으로 정해져 선택 단계가 없다(현재 구현이 이것). 그룹·오픈방에서는
두 갈래가 새로 생긴다.

- **대상자 지정** — 결제 전에 방 멤버 중 누구에게 줄지 프로필 아이콘으로 고르고, 결제 단계에서
  **선물 메시지를 방 전체에 보일지 받는 친구만 보게 할지** 선택한다. 이 가시성 축이 현재 없다.
- **선물게임** — "선물할 친구를 미리 정하지 않고" 보낸다. **랜덤 / 선착순 / 퀴즈 / 가위바위보**
  4종, 수신 가능 대상이 2명 이상인 방에서만 시작되고 **최대 100명**까지 받는다. 당첨자 사전
  지정 불가, 결과는 방 전원이 본다. 방에 대화가 하나도 없으면 시작되지 않는다.
- **코드선물** — 수신자 미지정. 선물코드를 방에 붙여넣어 먼저 등록한 사람이 가져가고 보낸 이
  프로필은 비노출이다.

**선물게임이 상태기계를 바꾼다.** 주문의 `receiverId` 가 결제 시점에 정해지지 않고 채팅방
상호작용으로 사후 결정되므로 "수신자 미정" 단계가 새로 필요하다. 현재 `newGiftOrder(seed)` 는
`receiverId` 를 필수로 받는다.

친구가 아니어도 보낼 수 있다는 점(오픈채팅방 멤버에게도 가능)은 현재 구조가 친구 관계를
전제하지 않으므로 이미 맞다.

### 7. 정산 — 카카오는 대화가 아니라 공유 장부로 풀었다

확인된 사실:

- **카카오페이 송금**은 계좌번호를 모르고 **카톡 친구 관계만으로** 보내며 그 경로는 무료다.
  친구가 아니면 '내 주변 송금'(블루투스·위치 기반)이 별도 경로다.
- **카카오뱅크**도 "계좌번호를 몰라도 카카오톡 친구에게 손쉬운 이체".
- **1/N 빵나누기**(2026년 1월 추가, 청소년용) — "카카오뱅크를 쓰지 않는 친구에게도 정산을
  요청할 수 있어요". 앱 밖까지 전달되는 링크성 구조다.
- **모임 단위 돈은 채팅방이 아니라 모임통장으로 처리된다.** 카톡 친구를 멤버로 초대하고,
  잔액·입출금을 멤버들이 실시간 공유하고, **AI 모임총무**가 회비·지출을 요약한다.

따라서 정산을 넣는다면 **패턴 C** 로 만든다 — 대화 메시지 하나가 아니라 초대된 멤버를 가진
공유 장부다.

**확인 불가**: 채팅방 `+` 메뉴에서 송금/정산을 여는 정확한 동선, 정산 요청 카드가 말풍선으로
어떻게 렌더링되는지, 요청받은 사람이 누르는 버튼의 라벨과 다음 단계, 1/N 자동 분할의 반올림
처리. 카카오톡 앱스토어 설명은 송금·지갑을 아예 언급하지 않는다.

## 현재 제품 경계 밖 — 화면에 자리를 만들지 않는다

Fastify + PostgreSQL 백엔드가 시스템 오브 레코드로 들어왔으므로 **"서버가 없어서 불가능"은 더
이상 분류 기준이 아니다.** 아래 항목은 기본 REST/WebSocket 서버만으로 끝나지 않고 별도 실시간
인프라, 장기 보관 정책, 외부 SDK 또는 모델 운영·개인정보 경계를 요구한다. 그래서 현재 제품
범위에서는 `out`으로 두며, 필요한 경계가 설계되기 전까지 `오픈 예정` 자리를 만들지 않는다.

| 서비스 | 현재 백엔드 외에 필요한 것 |
|---|---|
| 보이스톡 · 페이스톡 | WebRTC 미디어·시그널링, TURN, 통화 상태·푸시 운영 (실제로는 최대 10인 + 화면공유) |
| 톡클라우드 (구 톡서랍) | 장기 보관·백업, 암호화, 기기 복원, 대용량 객체 저장과 보존 정책 |
| 지도 · 친구위치 | 외부 지도 SDK·키, 위치 권한과 위치정보 보관 정책 |
| AI 대화 요약 · ChatGPT for Kakao | 모델 공급자·비밀 관리, 대화 전송 동의, 입력·출력 보존 정책 |

## 참고 — 카카오 서비스 전체 지형은 3층이다

무엇을 넣을 수 있는지 판단하는 기준이 된다.

- **1층, 카카오톡 안에 완전히 들어있는 것** — 일반채팅 · 비밀채팅 · 팀채팅 · 오픈채팍 · 숏폼 ·
  채팅방 폴더 · 보이스톡/페이스톡 · 통화 녹음 · 프로필/멀티프로필 · 펑 · 소식 피드 · 이모티콘 ·
  톡클라우드 · 카카오톡 지갑 · My 구독 · 채널 · 톡캘린더 · 같이가치 · 게임칩 · 예약하기 ·
  톡체크아웃 · AI 대화 요약 · ChatGPT for Kakao
- **2층, 카카오톡 안에서 전체화면 웹으로 열리는 독립 서비스** — 선물하기(`gift.kakao.com`) ·
  톡딜(`store.kakao.com`) · 메이커스(`makers.kakao.com`) · 이모티콘샵(`e.kakao.com`) ·
  톡캘린더 웹(`calendar.kakao.com`)
- **3층, 완전 별도 앱** — 카카오페이(+증권+손해보험) · 카카오뱅크 · 카카오맵 · 카카오 T ·
  카카오내비 · 카카오버스 · 카카오지하철 · 멜론 · 카카오페이지 · 카카오웹툰 · 픽코마 · 브런치 ·
  카카오스토리 · 지그재그 · 포스티 · 카나나 · 카카오워크

**선물하기를 전체화면 오버레이로 만든 것은 2층을 구현한 것이다.**

### 커머스 5개는 각자 장사 방식이 다르다

| 서비스 | 장사 방식 |
|---|---|
| **선물하기** | **구매자와 수령자가 다른 커머스** |
| 톡딜 | 공동구매 특가. 매일 17시 MD 큐레이션, 구매자수·거래액 실시간 랭킹 |
| 메이커스 | 수요를 먼저 모아 그만큼만 생산(재고 0 지향) |
| 쇼핑하우 | 직접 팔지 않고 값을 비교해 제휴몰로 넘김 |
| 쇼핑라이브 | 실시간 방송에 시간·재고를 묶어 판매 |

**톡스토어는 브랜드로 소멸한 것으로 보인다** — 공식 목록에 이름이 없고 `톡딜` 링크가
`store.kakao.com`(톡스토어 도메인)을 가리킨다. 쇼핑라이브는 큐레이션 페이지엔 있으나 전체
서비스 목록에서 누락돼 축소 신호다. 둘 다 **종료 확인이 아니라 "공식 목록에서 사라짐"** 이다.

### 개발자 API 목록이 카카오톡의 공개된 자료구조다

배열이 이렇다: **식별**(로그인·싱크) → **친구 그래프**(카카오톡 소셜: 프로필·친구 목록 조회) →
**쓰기 채널**(공유 · 메시지 · 메시지 템플릿 · 채널 · **톡캘린더**) → **수익화**(모먼트 · 키워드광고)
→ **지리·검색**(카카오맵 · 카카오내비 · Daum 검색).

**대화 내용을 읽는 API 는 공개돼 있지 않다** — 쓰기는 열고 읽기는 닫았다.

## 해결해야 할 사실 오류

조사가 현재 구현의 오류를 몇 개 찾았다. 로드맵과 별개로 고쳐야 한다.

### 선물 규칙이 실제와 다르다

`src/domain/gift.ts` 의 `GIFT_RULES` 는 프로토타입 단계에서 정한 값이다.

| 항목 | 현재 구현 | 실제 |
|---|---|---|
| 교환권 유효기간 | 90일 | **1년(367일)** |
| 연장 단위 | 90일 | **3개월** |
| 연장 횟수 | **1회만** | 반복 가능, **총 5년 상한** |
| 연장 가능 시점 | 아무 때나 | **만료 30일 전부터** |
| 만료 후 환불 | 90% 고정 | **5만원 이하 90% / 초과 95% / 포인트 100%** |
| 포인트 100% 환불 기한 | 없음 | **만료일부터 7일 이내** |
| 최종 환불 기한 | 없음 | **주문일부터 5년** |

**규칙의 성격이 바뀐다.** 현재는 횟수를 세지만 실제는 **누적 기간 상한 + 신청 시간창**이다.
`extensionsUsed` 대신 `paidAt + 5년` 을 상한으로 계산하고 `expiresAt - 30일 <= now` 조건을
`checkGiftAction` 에 넣는 것이 맞다. 환불도 단일 상수로 표현되지 않는다 — 금액 구간에 갈리고
**현금이냐 포인트냐** 축이 생겨 원장에 수단 필드가 필요하다.

여러 건 일괄 연장은 `선물함 > 선물비서 > 연장하기` 로 **한 번에 최대 30개**다. 할인 구매·이벤트
경품 교환권, 이미 만료된 교환권, 이미지로 받은 교환권은 연장할 수 없다.

만료 후 카카오 자체 공시 현금 환불 비율은 **확인 불가**(앱 내 신청 단계에서만 안내). 90%/95%는
공정거래위원회 신유형 상품권 표준약관 근거이고 2025-09-16 개정 내용은 2차 보도로만 확인했다.

출처: [교환권 유효기간](https://ccs.kakao.com/help?service=66&category=90&device=779),
[교환권 환불](https://ccs.kakao.com/help?service=66&category=90&device=780)

### 상품에 옵션 축이 없다

공식 선물하기 소개에 **"받는 사람이 색상·향 등 옵션을 직접 변경"** 이 명시돼 있다. `GiftOrder` 는
`productId` 와 결제 당시 가격만 들고 있다. 랭킹도 실제는 **성별·가격별**로 갈리는데 현재
`ranking()` 은 `recentBuyers` 내림차순 단일축이다.

### 배송상품과 교환권은 흐름이 완전히 다르다

| | 배송상품(실물) | 교환권(모바일 쿠폰) |
|---|---|---|
| 수령 절차 | 수신자가 **배송지 입력** 필요 | 입력 없이 즉시 보유 |
| 미수령 시 | 입력 기간 경과 → **주문 자동 취소·환불** | 유효기간 경과 → 연장 또는 환불 |
| 보낸 이 취소 | **배송 준비 시작 전**까지 | 수신자 **사용 전** + 구매자 취소 가능 기간 내 |
| 거절 | 배송요청 단계까지 가능, 배송중·완료는 불가 | 사용 전 가능 |

금액권(잔액 차감·부분 사용)과 교환권(1회 전액)의 차이는 **확인 불가**로 남았다. 현재는 교환권만
있고 부분 사용 개념이 없다.

### 하단 탭이 4개일 가능성이 높다

카카오 공식 카카오톡 소개와 App Store v26.7.3 기준 **친구 / 채팅 / 지금 / 더보기** 4개다.
**2025년 9월 15년 만의 대개편**에서 3번째 탭이 지금탭(오픈채팅 커뮤니티 + 숏폼 통합)이 되고
친구탭이 피드형으로 바뀌었다가, 반발로 **2025년 12월 15일부터 친구탭 첫 화면만 목록형으로
복원**됐다.

현재 구현은 `친구 · 채팅 · 오픈채팅 · 쇼핑 · 더보기` 5개이고 이는 2025년 9월 이전 레이아웃이다.
오픈채팅은 독립 탭이 아니고, `쇼핑` 탭은 어느 1차 출처에도 없다.

**미결정**: 참고했던 스크린샷을 개인정보 때문에 제거해 재확인할 수 없다. 실기 화면 확인이 필요하다.

## 조사 한계

`cs.kakao.com` · `ccs.kakao.com` 의 개별 도움말은 **JS 렌더링 + HTTP 429** 라서 정적 fetch 로
읽히지 않는다. 도움말 ID 를 범위로 훑는 fetch 루프는 30분 타임아웃으로 실패했으므로 쓰지 말고,
필요하면 브라우저로 실제 페이지를 열어야 한다.

검색 색인이 한국어 질의에 **네이버 도움말을 반복 반환**하는 경향이 강하다. 네이버 캘린더에는
'약속' · '수락/미정' · '공유 캘린더' · '마스터' 개념이 모두 있어 카카오 것으로 옮기면 틀린다.

미확인으로 남은 것: 정산 카드의 말풍선 렌더링, 채팅방 `+` 메뉴 항목 라벨, 금액권과 교환권의
차이, 멜론 이용권의 선물하기 등재 여부, 오픈채팅 강제퇴장·부방장 지정 경로, 앱 내 캘린더 진입
경로와 화면 뷰 구성.
