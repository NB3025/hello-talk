# 선물하기 참고 화면

실제 카카오톡 선물하기 화면 5장을 보고 정리한 구조 노트다.

**스크린샷 원본은 리포에 두지 않는다.** 실제 사용자의 이름과 프로필 사진이 찍혀 있어서
— 우리 프로젝트와 무관한 제3자의 개인정보다 — 버전 관리에 넣지 않고 지웠다. 아래 표기 중
사람 이름은 전부 `친구A` 같은 자리표시자로 바꾸었다. `.gitignore` 가
`references/**/*.png` 를 막고 있으므로 다시 넣어도 커밋되지 않는다.

개발에 필요한 것은 이미지가 아니라 **정보 계층**이고, 그건 이 문서가 들고 있다.

| 화면 | 내용 |
|---|---|
| 1 · 선물하기 홈 | 선물할 친구 선택 + 선물 테마 그리드 |
| 2 · 랭킹 | 카테고리 + 상품 2열 그리드 |
| 3 · 선물함 > 받은선물 | 교환권 카드 |
| 4 · 선물함 마이페이지 | 프로필 · 바로가기 · My 선물하기 |
| 5 · 카카오톡 더보기 탭 | 선물하기 진입점 |

---

## 먼저 알아야 할 것 — B안과 충돌한다

우리는 프로토타입에서 **B안(관계에서 파생 · 새 목적지 없음)** 을 골랐다. 선물하기를
별도 탭으로 만들지 않고 사람과 대화에 붙는 시트로만 두는 안이다.

그런데 실제 카카오톡 선물하기는 **전체 화면 서브앱**이다:

- 자기만의 상단바 — 뒤로 `‹`, 장바구니, "선물하기", 검색, **닫기 `✕`**
- 자기만의 가로 스크롤 탭 — `♥` 홈 · 랭킹 · 추석선물`특가` · 와인/위스키 · 럭셔리선물 …
- 자기만의 **하단 탭 5개** — 홈 · 카테고리 · (브랜드) · 위시 · 선물함

즉 카카오톡의 5탭 셸을 유지하는 게 아니라, 셸 위에 **또 하나의 앱을 덮는다.**
`✕` 로 닫으면 원래 카카오톡으로 돌아오는 구조다.

**다만 진입은 여전히 관계에서 온다.** 홈의 첫 섹션이 그 증거다 — 가로 캐러셀의 첫 카드가
노란 `+` 와 "선물할 친구를 선택해 주세요."이고, 그 뒤로 추천 친구들이 온다. 진입점도
친구 목록의 생일 행과 더보기 탭(5번 화면)의 아이콘 그리드다.

정리하면 실제 카카오톡은 **진입은 B안, 목적지는 A안**인 혼합이다. 우리가 B안을 고른 근거
("선물이 누구에게라는 맥락 없이 시작되지 않아야 한다")는 진입에 관한 것이고, 실제 앱도
그 부분은 지킨다. 카탈로그 브라우징이 시트에 갇혀 답답해진다고 지적했던 B안의 약점을
실제 앱은 **전체 화면 서브앱**으로 푼다.

→ **결정이 필요하다.** 시트를 전체 화면 오버레이로 승격할지, 시트 크기를 유지하고
카탈로그를 좁게 갈지. 구현 시작 전에 정한다.

## 01 · 선물하기 홈

- **상단바**: 장바구니 / "선물하기" / 검색 / `✕`
- **가로 스크롤 탭**: `♥`(위시) 홈 랭킹 추석선물`특가` 와인/위스키 럭셔리선물 …
  선택 탭은 검정 굵은 글씨 + 하단 2px 밑줄
- **선물할 친구 캐러셀** (회색 배경 섹션)
  - 첫 카드: 노란 원형 `+` + "선물할 친구를 선택해 주세요."
  - 이후 카드: 친구 사진 + 핑크 배지 `고마운 친구` + 이름(`친구A`) + 부제 `추석 추천 친구`
- **세그먼트 pill**: 선물 테마(선택, 흰 배경) / 카테고리 / 최근 본 — 회색 트랙 위 흰 알약
- **테마 그리드 5열 × 3행 = 15개**
  생일 · 추석선물`주목` · 맛있는선물 · 건강·비타민 · FOR ME
  가벼운선물 · 명품선물 · 스몰럭셔리 · 출산·돌 · 결혼·집들이
  프라다뷰티`광고` · 시원한선물 · 직장동료 · **교환권** · 합격·응원
  → 아이콘이 일러스트가 아니라 **실제 상품 사진**이다
- **광고 배너**: 굵은 제목 + 부제 + 우측 상품 이미지 + 우상단 `광고`
- **하단 탭 5개**: 홈 / 카테고리 / (원형 브랜드 이미지) / 위시 / 선물함(빨간 점)

가져올 것: 친구 선택이 **화면 최상단 첫 액션**이라는 배치. 우리 구현도 "누구에게"를
가장 먼저 묻는다.

## 02 · 랭킹

- **세그먼트 pill 3개**: 급상승 / 카테고리(선택) / 선물테마
- **카테고리 가로 스크롤**: 원형 상품 사진 + 라벨 — 카카오프렌즈, 레저·스포츠, 명품패션,
  책·음반티켓, 주류, 반려동물
- **필터 줄**: ✅ 무료배송 · 우측에 `09.09 14:00 기준 ⓘ` — 랭킹 갱신 시각을 명시한다
- **상품 카드 2열 그리드**
  - 좌상단 검정 사각 **순위 배지** (1, 2, …)
  - 이미지 하단 오버레이 pill: `🔒 최근 구매 121명`
  - 브랜드명 + `›`
  - 상품명 2줄 말줄임
  - 가격 굵게 (`165,000원`)
  - 태그 pill: `무료배송` `선물포장`
  - 하단 줄: 장바구니 아이콘 · `♡ 836` · 우측 `1/6` 페이지 인디케이터
  - 광고 카드는 `ⓘ 광고` 표기
- **플로팅 pill** (하단 중앙): `🎁 누구를 위한 선물인가요?` — 여기서도 받는 사람을 다시 묻는다

## 03 · 선물함 > 받은선물

- 광고 배너 (`[10% OFF] …` + `바로가기 ›`)
- **큰 제목**: "사용할 수 있는 선물이 1개 있어요" — 숫자를 문장에 넣는다
- 우측 `흔들기 설정` 버튼 + 툴팁 말풍선
- **탭**: `받은선물 1`(선택, 밑줄) / `사용완료 216` / `같이스…`
- **교환권 카드**
  - 회색 배경 카드 안에 브랜드 색 쿠폰 이미지 (맥도날드 노랑 + `50,000원`)
  - 우상단 빨간 원형 도장 **`사용중`** ← 상태를 도장으로 표현
  - 브랜드명 `맥도날드`
  - 상품명 `디지털 상품권 5만원권`
  - **`from.친구A`** — 보낸 사람을 굵게
  - 받은 시각 `2024.02.14 오후 01:37`

가져올 것: **상태를 도장으로** 표시하는 방식(`사용중` / 우리 모델의 `사용 완료`·`만료`),
그리고 `from.보낸사람` 표기. 로직 프로토타입
(`prototypes/gift-order-lifecycle.prototype.html`)의 상태 6개가 이 카드의 도장에 대응한다.

## 04 · 선물함 마이페이지

- **프로필 카드**: 아바타 + 이름, 그 아래 4개 바로가기 — 받은 선물 🎁 / 위시리스트 💗 /
  쿠폰 / 쇼핑포인트 (아이콘 + 라벨 세로 배치)
- **섹션 `혜택`**: 선물비서 · 선물하기 베프
- **섹션 `My 선물하기`**: 주문내역 · 픽업/GiftX 예약관리 · 친구의 위시리스트 ·
  친구의 기념일 · (선물 후기)

가져올 것: `친구의 기념일` — 우리 캘린더 슬라이스와 직접 연결되는 항목이다.
생일 → 선물 진입이 여기서도 반복된다.

## 05 · 카카오톡 더보기 탭 (진입점)

- 상단: "더보기" / 검색 / QR / 설정(빨간 점)
- 필터 pill: 홈(검정 선택) / 지갑 / 게임
- **pay 배너** (카카오 옐로): `pay 0원` + 송금 │ 자산 │ 결제
- **아이콘 그리드 4열 × 3행** (선 아이콘, 신규는 빨간 점)
  선물하기 · 받은선물 · 톡딜· · 이모티콘
  라이브쇼핑· · 메이커스 · 프렌즈· · AI국민비서
  모바일신분증 · 톡클라우드 · **캘린더** · 예약하기·
  + 페이지 인디케이터 3개
- **하단 탭 5개**: 친구 / 채팅`537` / 오픈채팅`999+` / 쇼핑 / 더보기·

가져올 것: 우리 `MoreScreen` 이 지금 목록 행 형태인데, 실제는 **4열 아이콘 그리드**다.
그리고 **선물하기와 받은선물이 별개 항목**으로 나란히 있고 **캘린더도 여기 있다** —
B안에서 이 둘을 더보기 안쪽에 둔 판단과 일치한다.

## 우리 구현에 반영할 것 (요약)

1. **"누구에게"를 먼저 묻는다.** 홈 최상단 친구 캐러셀 + 랭킹의 플로팅 pill 로 두 번 묻는다.
2. **선물 테마 그리드**가 카탈로그의 주 진입로다. 카테고리보다 테마(생일·직장동료·합격·응원)가
   앞에 온다 — 사람들이 상품이 아니라 **상황**으로 찾는다.
3. **교환권 카드의 상태는 도장**으로. 로직 프로토타입의 상태 6개를 그대로 매핑한다.
4. **`from.보낸사람`** 표기와 받은 시각을 카드에 넣는다.
5. `MoreScreen` 을 4열 아이콘 그리드로 바꾸고 선물하기·받은선물·캘린더를 나란히 둔다.
6. 랭킹에 **갱신 시각**을 표시한다(`09.09 14:00 기준`) — 순위가 실시간이 아님을 밝히는 장치.

## 열린 결정

- 선물하기를 **전체 화면 서브앱**으로 승격할지, B안대로 시트에 유지할지.
- 상품 이미지를 무엇으로 할지. 실제 사진은 쓸 수 없으므로 이모지·색 블록·자체 일러스트 중 택일.
- 결제는 모의로 끝낼지, 주문 상태만 남길지(로직 프로토타입은 모의 결제 전제).
